The Endpoints tab is where you register the model providers you want to evaluate against. Add an Ollama server, an OpenAI-compatible API, or a Kilo Gateway instance here so the GUI knows where to send prompts. Each endpoint stores its base URL, optional API key, and provider type, and you can test connectivity with one click. Once saved, endpoints appear in the list below and can be selected when registering models or generating reports.

Pick a memorable label like "Local Ollama" or "Prod OpenAI". This is only for display in the GUI; it does not affect the API request.
Select the SSH gateway endpoint. All Ollama models are on the gateway at 10.133.7.211 with 8GB GPU. Available models: gpt-oss, gemma3:4b, qwen3:4b, llama3.2:1b, tinyllama, bge-m3. Choose an auto-discovered endpoint or pick Custom to type a URL manually.
Paste a bearer token or API key if the provider requires authentication. Leave blank for unauthenticated gateway endpoints. Keys are stored locally in the GUI data directory and never sent to external servers.
Select the provider type so the GUI knows which API paths to query. Ollama uses /api/tags, OpenAI-compatible and Kilo Gateway use /models. Changing this after saving does not update existing connections; remove and re-add the endpoint if needed.

The Models tab lets you register the specific model IDs you want to evaluate. You can either add them manually or click Auto-Detect to query your saved endpoints and pull the model list automatically. Each model is linked to an endpoint so the GUI knows where to send requests. Models added here appear as selectable chips in the Generate Reports tab and can be removed at any time.

Select a model from the dropdown populated by your configured endpoints, or choose Custom... to enter a model ID manually. The exact identifier is sent directly to the provider without modification.
Choose which saved endpoint this model should use. Endpoints are automatically tested for availability; grayed-out options are currently unreachable. You can add more endpoints in the Endpoints tab if needed.

Use the Generate Reports tab to run the standard evaluation prompt suite against your selected models. First pick one or more models, then choose a pre-built prompt package or customize prompts. Click Generate Reports to start the run; the backend will execute the evaluation script and save PDFs plus raw telemetry. Output appears in the console below the form and is also recorded in the Telemetry Wall.

Click model chips to add or remove them from the current run. Selected models appear highlighted. Use Select All/None for bulk actions. Models are drawn from the Models tab.

The Reports tab lists every PDF generated by the Generate Reports action and stores them for in-browser viewing. Use the search box to filter by filename, then click View PDF to open the built-in PDF.js viewer with page navigation. You can also open the original PDF in a new browser tab or download it for offline review. Reports are served directly from the server and persist across reboots as long as the file remains in the reports directory.
