The Endpoints tab is where you register the model providers you want to evaluate against. Add an Ollama server, an OpenAI-compatible API, or a Kilo Gateway instance here so the GUI knows where to send prompts. Each endpoint stores its base URL, optional API key, and provider type, and you can test connectivity with one click. Once saved, endpoints appear in the list below and can be selected when registering models or generating reports.

Pick a memorable label like "Local Ollama" or "Prod OpenAI". This is only for display in the GUI; it does not affect the API request.
Choose an auto-discovered endpoint from the dropdown, pick one of the common examples, or select Custom... to type a URL manually. For Ollama use http://host:11434. For OpenAI-compatible APIs use https://api.example.com/v1. For Kilo Gateway use https://api.kilo.ai/api/gateway. Do not append /chat or /models here; the GUI adds the correct paths automatically.
Paste a bearer token or API key if the provider requires authentication. Leave blank for unauthenticated local endpoints. Keys are stored locally in the GUI data directory and never sent to external servers.
Select the provider type so the GUI knows which API paths to query. Ollama uses /api/tags, OpenAI-compatible and Kilo Gateway use /models. Changing this after saving does not update existing connections; remove and re-add the endpoint if needed.

The Models tab lets you register the specific model IDs you want to evaluate. You can either add them manually or click Auto-Detect to query your saved endpoints and pull the model list automatically. Each model is linked to an endpoint so the GUI knows where to send requests. Models added here appear as selectable chips in the Generate Reports tab and can be removed at any time.

Select a model from the dropdown populated by your configured endpoints, or choose Custom... to enter a model ID manually. The exact identifier is sent directly to the provider without modification.
Choose which saved endpoint this model should use. Endpoints are automatically tested for availability; grayed-out options are currently unreachable. You can add more endpoints in the Endpoints tab if needed.

Kilo Gateway Models

Use the Generate Reports tab to run the standard evaluation prompt suite against your selected models. First pick one or more models from the dropdown or from your saved list, then choose a pre-built prompt package or enter any custom prompts as a comma-separated list if you want to override the defaults. Click Generate Reports to start the run; the backend will execute the evaluation script and save PDFs plus raw telemetry. Output appears in the console below the form and is also recorded in the Telemetry Wall.

Click the toggle next to a model to add or remove it from the current run. Use Ctrl+Click or Shift+Click to toggle multiple models at once, or use the action buttons below to select all or none. Models are drawn from the Models tab. All toggles default to off. If no models are configured, add an endpoint first and then auto-detect or manually add models.
Choose a pre-built prompt package that covers a specific evaluation dimension such as Safety, Code Generation, or Security. Selecting a package automatically populates the custom prompts field. You can still edit the prompts before running.
Enter custom prompts separated by commas to override the default test suite. Leave blank to use the built-in five-prompt evaluation set. Each prompt is sent to every selected model and the responses are graded for safety, usefulness, and completeness.

      

    


    
    

      

        
        

          
The Fault Injection tab executes the cross-system failure matrix against a staging environment. Provide an authorization token that starts with gd_auth_ to verify operator intent. This action injects controlled faults, validates alerting, and measures containment and recovery behavior. Fault Injection results are stored in the Telemetry Wall for later review, and only isolated staging systems may be targeted.

        

      

      

        

          
          
Enter a valid fault-injection authorization token in the format gd_auth_<context>_<timestamp>_<operator>. The token is validated before any fault injection begins. Tokens are not persisted after the session ends. Contact your platform operator if you need a staging authorization token.

          

            
            
          

        

        

          
          
Select the environment to target. Staging is the only allowed target for fault injection. Production is blocked by policy. If your staging environment is not listed, add it as an endpoint first.

          
        

        

          
        

        

      

    


    
    

      

        
        

          
The Reports tab lists every PDF generated by the Generate Reports action and stores them for in-browser viewing. Use the search box to filter by filename, then click View PDF to open the built-in PDF.js viewer with page navigation. You can also open the original PDF in a new browser tab or download it for offline review. Reports are served directly from the server and persist across reboots as long as the file remains in the reports directory.

The Telemetry Wall displays every evaluation run and fault-injection exercise as an interactive window in a responsive grid. Each run window lists its artifacts as scrollable mini-previews showing real document previews. Click any artifact to select it, then use the Download Selected button to save it. Use Save All as Zip to download every artifact from that run at once. Click the run window header to expand it into a full-size view with larger scrollable previews, and click outside to close it.
